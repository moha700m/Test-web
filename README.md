# اختبر موقعك — Mohammed Lab

خدمة عربية لفحص أداء المواقع التي تملكها. واجهة كحلية وحمراء، تحقق ملكية بملف عام، طلبات HTTP فعلية، إيقاف يدوي، وتصدير تقرير JSON.

## تشغيل سريع

ثبّت Node.js 24 أو أحدث، ثم داخل هذا المجلد:

```sh
npm ci
npm run build
npm start
```

افتح `http://localhost:3000`. على Windows يمكنك تشغيل `Start-Windows.cmd` بعد تثبيت Node.js. قاعدة SQLite تُنشأ تلقائيًا محليًا في `.sites-runtime`.

## اختبر موقعك

1. أدخل رابط HTTPS الأصلي لمشروعك على Vercel أو Netlify أو Cloudflare Pages أو GitHub Pages أو Replit.
2. انسخ البرومبت الذي تولّده الخدمة إلى أداة البناء. انشر ملف `public/.well-known/site-check.txt` بالمحتوى المطلوب؛ يجب أن يرجع 200 مباشرةً دون تحويل أو تسجيل دخول.
3. تحقق من الملكية، واختر فحصًا سريعًا أو حملًا خفيفًا أو محدودًا، ثم ابدأ.
4. راجع متوسط الاستجابة وp95 ونسبة نجاح الطلبات، أو حمّل التقرير.

الفحص يستخدم اتصالًا واحدًا، حتى 3 طلبات/ثانية، حتى 20 ثانية و60 طلبًا. لكل موقع اختبار واحد في الدقيقة. يتوقف عند 429 أو 503 أو ثلاثة أخطاء متتالية. إثبات الملكية مرتبط بجلسة المتصفح، ينتهي بعد 30 دقيقة، ويُستهلك بعد اختبار واحد.

الزمن المقاس هو زمن استلام رؤوس استجابة HTTP من الخادم الذي يشغّل الخدمة؛ لا يقيس تحميل الصفحة الكامل أو JavaScript أو السعة القصوى. التحويلات لا تُتبع. الروابط الخاصة وIP والدومينات المخصصة غير مدعومة في هذه النسخة. لا تُرسل كوكيز المستخدم أو بيانات دخوله إلى الموقع المختبر.

## للمطور والنشر

```sh
npm run dev
npm test
npm run build
```

واجهة React/Vite، API مشتركة بين Node وCloudflare Worker، وSQLite/D1. يحوي `dist/client` ملفات الواجهة و`dist/server` كود Worker. يجب ربط قاعدة D1 باسم `DB` وتطبيق ترحيلات SQL داخل `drizzle` قبل نشر Worker؛ لا يكفي نشر ملفات الواجهة وحدها. ملف `.openai/hosting.json` يحدد الربط المطلوب دون أي بيانات حساب.

خادم Node يستمع على 127.0.0.1. عند نشره خلف وكيل HTTPS، اضبط `PUBLIC_ORIGIN` على أصل الخدمة العام الدقيق، مثل `https://check.example.com`، ومرّر الطلبات إلى الخادم المحلي. `PORT` يحدد المنفذ. تأكد من HTTPS وتخزين قاعدة البيانات على قرص دائم. لا تضع ملف قاعدة البيانات أو `.env` في ملفات الواجهة العامة.

## النشر على Vercel

استورد مستودع `moha700m/Test-web`. إعدادات Vite ومجلد الواجهة ودوال API موجودة في `vercel.json`.

اربط قاعدة PostgreSQL دائمة بالمشروع واضبط `DATABASE_URL` (أو `POSTGRES_URL`) في بيئة Production وPreview. احفظ كلمة المرور في متغيرات البيئة على Vercel فقط؛ لا تضعها في GitHub أو متغير يبدأ بـ `VITE_`.

أمر البناء المخصص ينشئ جداول الخدمة والفهارس المطلوبة دون حذف بيانات، ثم يبني الواجهة. يجب أن يسمح دور قاعدة البيانات بإنشاء هذه الجداول. إذا لم توجد قاعدة بيانات سيفشل البناء عمدًا بدل نشر واجهة بفحص معطل. تستخدم الدوال قاعدة PostgreSQL المشتركة للحفاظ على إثبات الملكية وحدود الاختبار بين نسخ Vercel المختلفة. يستخدم التشغيل المحلي SQLite كما سبق.

لم يكتمل النشر العام من هذه الجلسة بعد. لا تتضمن الخدمة اشتراكات أو دفعًا أو حسابات مستخدمين.
